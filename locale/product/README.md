# Product localizer · RU → KK

Независимый Node.js 20+ инструмент. Запуск из любой директории (рекомендуется из `locale/product`); путь к серверу по умолчанию `http://10.10.3.80:1337`. Для других коллекций будут отдельные `locale/<collection>/localizer.mjs`.

## Запуск (PowerShell)

```powershell
cd locale/product
node localizer.mjs --self-test
node localizer.mjs --limit=10
node localizer.mjs --id=DOCUMENT_ID
node localizer.mjs --apply --id=DOCUMENT_ID
node localizer.mjs --apply
```

Для точечного пилота замени `DOCUMENT_ID` на настоящий `documentId` Product. Этот режим не выгружает весь список 20 000 товаров. После пилота для нового полного прохода используй `--new-run`, чтобы прежние обработанные ID не пропускались.

При запуске вставь **Admin JWT** из текущей сессии Strapi в скрытый запрос терминала. Токен не помещается в файл, репозиторий и отчёт. Можно передать переменную окружения `STRAPI_JWT`, но не записывать её в файлы GitHub. **Запись отключена**, пока не указан `--apply`. **Реальный пилот на живом Strapi новой версии ещё не подтверждён.**

Если у Product нет KK: Strapi 5 документирует создание локали существующего документа через `PUT /api/products/:documentId?locale=kk&status=draft` с `{"data":{...}}`. Для этого требуется **отдельный токен Content API** с разрешением на создание локали, переданный как `STRAPI_API_TOKEN`. Admin JWT не является гарантированной заменой. Если токена нет — `blocked_no_content_api_token`; попыток непроверенного Admin POST нет. При создании локализуемые тексты остаются пустыми, required-поля блокируют создание. Перед массовым применением этого пути нужен live-пилот.

## Работа

- Получает из Content Manager **только список RU documentId** (это не глобальный backup); для каждого Product отдельно читает актуальные RU/KK Draft и KK Published и все root relations с полной пагинацией.
- Сверяет и при необходимости переносит из RU все root relations, все boolean **кроме `InStock`**, все media (даже если поле ошибочно отмечено localized), `name`. Не переносит KK локализуемые тексты; сохраняет `KK.key`. Другие shared поля, если отличаются, выводит как `unmanaged_shared`, не записывает вслепую.
- Перед изменением проверяет, что у всех связанных справочников есть KK. Если KK Draft без Published — публикует KK справочник с отдельным backup и GET-проверкой; если KK нет — блокирует только Product.
- Точечный backup создаёт **до первой записи**. Далее Save KK (если нужен), GET, Publish KK (если нужен), GET. RU и KK.key защищены postflight; `InStock` не включается в payload/сверку. Если проверка не пройдена, backup остаётся в `pending/`, **повторить запись автоматически запрещено**.
- Запускает постоянный пул работников: завершивший товар сразу берёт следующий. Параллельность регулируется `--workers=8` (1–32) и `--requests=24` (1–80); при 429/503 число одновременных запросов снижается. Retry применяется **только к GET**, не к PUT/POST.

## Результат и продолжение

В `localizer-state/audit/` или `localizer-state/apply/` (относительно текущей директории) создаются `report.csv`, `progress.jsonl`, `summary.json`, `pending/`. Все статусы и ошибки выводятся **для конкретного Product**. При перезапуске используется checkpoint; backup неопределённой записи не перезаписывается и не удаляется автоматически.

Для **нового полного прохода** после завершения предыдущего используй `--new-run` вместе с обычными параметрами: предыдущая директория будет переименована в архив, а не удалена. **Не запускай `--new-run`, если есть неразобранные файлы в `pending/`**.

```powershell
node localizer.mjs --new-run --apply --workers=12 --requests=32
```

При известном незавершённом STOP старого DIOR pipeline Product `fajndt11d4br9jmuy32n9xq9` исключён из автоматической записи (`blocked_legacy_unresolved`). Снимать блокировку через `--allow-legacy-unresolved` только после успешной ручной сверки старого backup и разрешения STOP.

**Ограничение:** локальный self-test не заменяет live-пилот. Без прав на Content API создание новых KK не запускается; существующие KK Product можно нормализовать с Admin JWT.
