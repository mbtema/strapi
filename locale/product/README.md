# Product: RU → KK (Strapi Admin)

Эта папка содержит инструменты **только для коллекции `api::product.product`**. Скрипты запускаются в DevTools → Console авторизованного Strapi Admin; перед запуском открывают соответствующую карточку Product (кроме аудита бренда). Общая диагностика версии Strapi и документация по i18n остаются на уровень выше, в `locale/`.

## Текущий инструмент

- `product-kk-guarded-pilot.js` — пилот **одного** Product: получение схемы, снимок RU Draft/Published и relations, проверка отсутствия KK, формирование PUT из общих полей RU, запись только по отдельному подтверждению, затем postflight со сравнением. **Не batch**. RU может перейти в `modified` даже без потери данных. Автоматическая публикация в скрипте отсутствует.
- [`product-kk-publish-pilot.js`](./product-kk-publish-pilot.js) — **непроверенный на живой CMS** тест публикации только Product `eio2evn0avkjzrsjawn5wtpt`, после безопасного создания KK предыдущим скриптом. Сначала read-only dry-run RU/KK Draft+Published, схема, required/localized/shared, все relations и JSON. Обязательные пустые поля или несовпадение общих полей блокируют публикацию. После отдельного подтверждения: Publish KK с полным payload её поддержанных полей и `locale=kk` → GET и сверка RU/KK → Publish RU с полным payload и `locale=ru` → GET и итоговая сверка; остановка при любом расхождении. **Никаких автоматических повторов, rollback, batch, автоподстановки переводов или создания KK.**

## Диагностика и одноразовые проверки

- `product-i18n-schema-audit.js` — чтение схемы локализации Product и RU/KK (только GET).
- `product-kk-preflight.js` и `product-kk-postflight.js` — ранняя read-only диагностика на фиксированном тестовом Product; не заменяют guarded pilot.
- `product-kk-ru-versions-check.js` — чтение/сравнение RU Draft и Published для фиксированного Product.
- `dior-product-kk-candidates-audit.js` — одноразовый read-only аудит products одного бренда; **не является частью будущего общего Product batch**.

## Правило для следующих операций

Для создания KK использовать схему Product: все поля с отключённой локализацией, включая media и другие поддерживаемые типы, передавать из актуального RU; до и после write сравнивать бизнес-поля, медиа и все relation IDs. Локализуемые required-поля KK требуют отдельной стратегии заполнения и проверки перед Publish. Публикация RU и KK — отдельный, пока **не проверенный на живой CMS** экспериментальный этап с верификацией. Скрипт публикации нельзя запускать вместо создания KK. Не использовать текущие скрипты для массового создания локалей.
